# 旅图 TripMap 产品战略

更新时间：2026-07-29

## 北极星

旅图是一个 **实时在线、AI 优先的旅行操作系统**。用户不需要理解数据表、同步队列或功能入口，只需要查看当前旅行，或直接说出目标；AI 应结合账号中的行程、票据、资料和实时 Provider 信息，完成查询、规划、预览、执行、跟踪和恢复。

产品默认假设用户已登录并在线。云端账号状态是目标事实源，跨设备变化应实时收敛；本机存储服务于启动速度、弱网容错和应急查看，不再定义产品身份。

## 产品原则

1. **在线状态优先**：账号数据、协作状态、AI 任务和实时事实以云端为准。
2. **AI 是主入口**：自然语言、上下文按钮和主动提醒都进入同一 Action Gateway，而不是分散的关键词路由和表单。
3. **完成任务优先**：AI 返回动作结果、目标页面或可执行预览，不用大段说明替代操作。
4. **实时事实优先**：地点、营业时间、路线、交通、天气、票价和票务状态应由 Provider 查询，并携带来源与新鲜度。
5. **界面保持安静**：首页、每日页和详情页先展示行程与当前状态；AI 只显示一句结论、必要影响和一个主操作。
6. **离线是韧性能力**：离线时可读取最近缓存、记录有限修改并等待续传，但不把离线降级包装成完整实时能力。
7. **安全是默认实现**：最小权限、密钥隔离、来源校验、审计和高风险确认由系统强制，不作为占据主界面的营销文案。

## UI V3 产品体验

状态：**Target**

第三次 UI 重构不是换色或缩小现有卡片，而是围绕“今天、下一站、导航、票据和一句话执行”重建信息架构。完整规范见 [UI V3 重构规范](UI_REFACTOR_V3.md)。

已锁定的产品决定：

- 移动端主导航固定为“今日、行程、收件箱、我的”四个顶层目的地。
- AI 是所有业务页面标题栏中的统一命令，不作为 Tab，也不保留常驻底部输入框。
- 点击 AI 打开上下文 Action Sheet；只读动作直接完成，写入继续使用真实预览和一次最终确认。
- 搜索是标题栏或内容内的上下文命令，不占用独立底部 Tab。
- 行程只保留“日程、地图、资料、费用”一行上下文切换；总览内容进入“今日”和“日程”。
- 首页、日程、地点详情、票据和收件箱首先展示真实旅行对象，不首先展示统计、建议、设置或诊断。
- 移动、平板和桌面共享业务语义，但分别使用底部导航、Navigation Rail 和主从布局。
- 生成式效果图用于方向探索，真实 React 组件和固定状态 Golden Screenshots 是最终视觉依据。

成功体验的基本约束：

- 用户打开应用 3 秒内能看清今天去哪、下一站和关键票据。
- 查看今日安排不超过 1 次点击，打开票据、导航和编辑行程不超过 3 次点击。
- AI 从任意业务页面 1 次点击可达，关闭时不占据内容区域。
- 同一视口不重复显示旅行名称、日期、统计、地址或地图入口。
- 同一时刻最多展开一个固定底部交互面，AI、地图地点卡和底部导航不能层叠遮挡。

## 目标体验

### 打开应用

- 立即看到当前旅行、今天的安排、下一站、关键票据和实时变化。
- AI 只在存在可执行变化时出现紧凑提示，例如“航班延误 35 分钟，已准备调整方案”。
- 设置、资料建议、同步诊断和技术状态默认收起，只在需要处理时展开。

### 直接告诉 AI

用户可以说：

- “找一下爱丁堡的门票。”
- “补全第一站地点信息。”
- “把今天因为下雨受影响的安排重新排一下。”
- “检查这趟旅行还缺什么，并一次修好。”
- “把酒店、交通和门票费用汇总成人均预算。”

AI 应自动完成上下文识别、必要的实时查询、动作规划和本地合同校验。只读动作直接完成；需要写入的组合计划只出现一次清晰确认；部分失败只重试失败步骤。

### 实时变化

- 账号、协作成员和后台任务变化通过实时订阅更新，不依赖用户手动刷新。
- 航班、铁路、天气、营业时间、路线和票务事实显示来源、查询时间和有效期。
- 事实过期时自动刷新或明确降级，不继续展示为当前事实。

## 目标数据架构

### 云端事实源

- Supabase/Postgres 保存账号旅行、行程对象、票据 metadata、协作状态、智能任务和操作历史。
- Realtime 或等价事件通道把对象变化推送到已登录设备。
- 服务端版本、幂等键和事件记录决定写入顺序、冲突和重试结果。
- 票据原件和资料附件使用受控对象存储，metadata 与文件生命周期保持一致。

### 本机边缘缓存

- IndexedDB 保存最近使用的旅行、待上传操作和必要附件缓存。
- 本机写入必须带服务端基线版本；在线时立即提交，弱网或离线时进入 outbox。
- 恢复连接后自动重放并与云端事实源收敛。
- 本机缓存丢失不能导致账号旅行丢失；清除缓存后应可从云端恢复。

### 服务端动作执行

- Provider 调用、AI 规划、异步任务和需要统一审计的写入逐步迁移到受控服务端执行层。
- 浏览器只提交语义目标、已批准计划和必要上下文，不提交任意函数名、SQL、路由地址或 Provider 密钥。
- 长任务返回 job ID，并通过实时状态更新展示 `queued / running / needs_input / completed / failed`。

## AI Action Gateway 目标

每个动作继续声明版本、输入 schema、上下文要求、风险、预览、执行、幂等和重试策略。Provider 只能从注册表选择动作和语义目标。

风险模型：

- **只读查询和导航**：自动执行。
- **可逆、低风险写入**：在一个组合计划中一次确认后执行。
- **外部副作用或高风险写入**：付款、取消订单、发送消息、删除云端原件、权限修改等保持单独明确确认。
- **未知或越权动作**：拒绝执行并记录审计事件。

AI 负责理解、规划、选择工具和解释结果；本地或服务端动作执行器仍是最终事实源。模型不能绕过 schema、权限、状态版本、幂等或确认策略。

## 实时 Provider 范围

| 能力 | 目标数据 | 基本要求 |
| --- | --- | --- |
| Place | 地址、坐标、营业时间、电话、官网、照片 | source、observedAt、字段级有效期 |
| Route | ETA、距离、交通方式、交通状况 | 出发时间、Provider、缓存期限 |
| Transit | 班次、站点、换乘、延误 | 时区、服务日期、实时/计划标记 |
| Flight / Rail | 状态、航站楼、站台、延误、取消 | 订单匹配、更新时间、来源 |
| Weather | 小时级天气、预警、体感 | 地点、时间窗、更新时间 |
| Ticket / Booking | 票据状态、使用时间、变更提醒 | 账号授权、来源、审计 |
| Search | 活动、公告、临时关闭、价格 | 可点击来源、抓取时间、置信度 |

没有来源或已过有效期的数据可以作为建议线索，但不能显示为当前事实。

## 隐私与安全基线

隐私不再作为主要产品卖点或大块界面内容，但以下边界保持强制：

- Provider 密钥、service role、Authorization 和云端 token 不进入前端构建、AI 上下文或日志。
- AI 和 Provider 请求按动作最小化字段，并由服务端再次校验。
- 证件、票据原件和联系人等敏感内容只在任务确实需要且权限允许时读取。
- 高风险操作保留确认、幂等、审计和撤销/补偿路径。
- 用户只在需要作出数据范围决定时看到简短权限说明，不需要管理底层技术开关。

## 成功指标

- AI 指令到完成结果的成功率和中位耗时。
- 需要用户手动寻找页面或重复输入的次数。
- 实时事实带来源率、过期率和刷新成功率。
- 在线写入到其他设备可见的 P50/P95 延迟。
- 组合计划一次确认完成率、部分失败恢复率和重复执行率。
- 核心旅行在弱网恢复后的自动收敛率。
- 首页与每日页首屏有效内容占比，及 AI 大段文案出现率。

## 文档状态规则

- **Current**：已经由代码、测试和生产配置支持。
- **Target**：已确定方向，但仍需实施。
- **Historical**：保留当时事实，不代表当前产品方向。

所有架构和路线图文档都必须明确使用其中一种状态，避免把目标能力写成现状，也避免用旧的本地优先定位约束新设计。
