# TripMap UI V3 重构规范

更新时间：2026-08-04

状态：**Target**

本文是第三次 UI 重构的规范性决策文档。上游产品合同是 [产品定位与核心体验](PRODUCT_POSITIONING.md)；本文把其中的用户、任务和旅行阶段转译为信息架构、视觉系统、组件规则、响应式行为、AI 交互、无障碍、验证门槛和实施顺序。当前已上线行为仍以 [项目状态](PROJECT_STATUS.md) 为准；本文不得被引用为“已经上线”的证明。

## 1. 目标与适用范围

TripMap UI V3 要把当前功能完整但层级复杂的 PWA，收敛为接近产品级原生旅行 App 的体验。V3 的首要目标不是展示 AI 或地图能力，而是让复杂自由行组织者始终知道当前阶段和下一步：

- 打开应用后 3 秒内看清旅行所处阶段、唯一下一步和相关真实对象。
- 查看今日安排不超过 1 次点击，打开票据、导航和编辑行程不超过 3 次点击。
- AI 从任意业务页面 1 次点击唤起，但未主动打开时不占据内容区域。
- 一个屏幕只承担一个主要任务、一个主操作和最多两层导航。
- 旅行对象和实时变化优先，设置、诊断、Provider、同步和配额说明默认隐藏。
- 视觉简洁不以删除能力为代价，而通过稳定层级、渐进披露和上下文操作减少负担。

V3 只重构展示与交互层。除非单独立项，不改变数据库 schema、云端语义、Provider 合同、AI 数据边界、票据 Blob、路线缓存和确认风险策略。

## 2. 规范词语

- **必须**：实现和评审不得偏离。
- **应该**：默认遵守；偏离时必须在 PR 中解释原因和替代验证。
- **可以**：允许按具体页面选择。
- **Current**：代码、测试和生产配置已经支持。
- **Target**：已决定但尚未全部实现。
- **Historical**：保留当时证据，不代表当前方向。

## 3. 当前审查结论

### Current

- 全局顶栏、底部导航和全局 AI 输入框构成多层固定区域，部分页面依靠大底部 padding 规避遮挡。
- 首页和 Trip Workspace 重复显示旅行名称、日期、目的地和统计。
- Trip、Day、Map、Documents 页面存在全局导航、旅行导航和页面标签叠加。
- AI 展开状态可以覆盖地图、地点卡和首屏主要内容。
- Item Detail 使用无真实内容的渐变头图，关键地址、导航和票据信息被推到首屏以下。
- Ticket Library 在真实画廊之前展示多层导航、统计、筛选和新增控件。
- Inbox 的零统计、连接器和 Provider 状态比用户资料本身更突出。
- Settings 已有折叠分类，但一级列表仍直接暴露同步、Provider、缓存和隐私等技术模型。
- 行程点编辑表单一次暴露时区、坐标、交通和跨日等高级字段。
- 多个核心页面和组件超过 1,000 行，展示状态、业务状态和异步流程耦合。

### Target

- 全局 App Shell 只保留一个顶栏和一个主导航。
- AI 从常驻输入框改为按需打开的 Action Sheet。
- “今日”按未建旅行、出发前、旅行中和旅行后切换内容重心；地图只在移动决策中成为主视觉。
- 首页、日程、地图、详情和资料首先展示真实旅行对象。
- 待整理材料并入“资料”，不再占据永久一级导航。
- 页面结构从“功能卡片集合”改为“内容列表、分组区块和上下文操作”。
- 移动端使用原生式 Push 导航；平板和桌面使用自适应主从布局。

## 4. 设计权威层级

从高到低依次为：

1. [产品定位与核心体验](PRODUCT_POSITIONING.md) 中的用户、任务、阶段和产品边界。
2. 本文和 [Design System](DESIGN_SYSTEM.md) 中的规范性规则。
3. `src/index.css` 中的语义 Tokens 与 V3 基础组件实现。
4. 真实 React 组件在固定测试数据和固定视口下生成的 Golden Screenshots。
5. Apple Human Interface Guidelines、Material Design 3、WCAG 2.2 和 WAI-ARIA APG。
6. Stitch、ImageGen 或 Figma 中的效果图。

生成式效果图用于选择层级、密度和视觉方向，不是精确中文、像素尺寸、组件状态或交互行为的最终依据。效果图与真实代码冲突时，以规范文档和通过验收的真实组件为准。

外部基础规范：

- [Apple Human Interface Guidelines](https://developer.apple.com/design/human-interface-guidelines)
- [Apple Tab Bars](https://developer.apple.com/design/human-interface-guidelines/tab-bars)
- [Apple Toolbars](https://developer.apple.com/design/human-interface-guidelines/toolbars)
- [Apple Layout And Safe Areas](https://developer.apple.com/design/human-interface-guidelines/layout)
- [Material Design 3](https://m3.material.io/)
- [WCAG 2.2](https://www.w3.org/TR/WCAG22/)
- [WAI-ARIA Authoring Practices Guide](https://www.w3.org/WAI/ARIA/apg/)

TripMap 不照搬单个平台的视觉皮肤。HIG 主要约束移动信息架构和导航，Material 3 用于交叉校验 Android 触控和 Bottom Sheet 行为，WCAG 与 APG 是 Web/PWA 的无障碍底线。

## 6. 效果图与设计锁定流程

1. 使用真实代码和固定测试数据捕获当前基线。
2. 先选择一个明确旅行阶段和核心任务，不使用“功能齐全的今日页”代替设计 brief。
3. 以 `390 x 844` 的该阶段核心页面为主屏，附带当前截图、产品定位和现有品牌 Tokens，使用 ImageGen 生成 3 个独立方向。
4. 三个方向必须在信息层级、内容密度和交互组织上真正不同，不能只换颜色。
5. 用户只需完成一次方向选择；选择后不得逐页重新发明视觉语言。
6. 把选中方向写入 `DESIGN.md`，并在 Stitch 建立一个版本化 Design System。
7. 使用同一 Design System 生成“出发前今日、旅行中今日、日程、地点详情、资料、AI Action Sheet”六个关键屏幕。
8. 先在真实代码中完成“导入材料 → 出发前今日 → 旅行中下一步 → 打开票据”的纵向切片。
9. 使用相同视口、数据和状态并排比较效果图与实现截图，修复层级、间距、字体、边界、溢出和遮挡。
10. 纵向切片通过后，真实代码截图替代生成效果图成为 Golden Screenshot。

效果图不负责精确生成中文长文本。所有真实文案、换行、截断和动态状态必须在代码中验证。

### V3.0 视觉方向决策状态

- **Historical（2026-07-30）**：曾选择方案 2 的视觉语言与方案 3 的地图优先层级，并据此完成一轮实现和 Golden 验证。
- **Historical（2026-08-04）**：在当前真实界面基础上继续生成的三套地图主导方案均被用户否决。结论不是“再润色地图”，而是旧 brief 把技术能力和单一旅行中场景误当成完整产品定位。
- **Selected Target（2026-08-04）**：先按 [产品定位与核心体验](PRODUCT_POSITIONING.md) 锁定阶段化信息架构，再生成跨场景方向。最终采用“第一套左上角出发前首页的信息组织 + 第二套随身旅夹视觉系统 + 第三套资料编辑式列表”的组合，完整合同见 [DESIGN.md](DESIGN.md)。

Selected Target 不得改变以下合同：

- 四项主导航为 `今日 | 行程 | 资料 | 我的`；待整理材料属于“资料”的状态。
- “今日”按旅行阶段变化，地图仅在移动决策时成为主视觉。
- 按需 AI Action Sheet、搜索命令、真实票据缩略图和渐进披露保持一致。
- 不增加宣传 Hero、大块建议、重复旅行摘要、嵌套卡片或常驻 AI 输入框。
- 视觉选择不能重开数据合同或风险确认决策，也不能用效果图事实覆盖真实旅行数据。
- 选择结果、日期、关键理由、允许调整项和完整页面图集写入 `docs/DESIGN.md`；真实实现与 Golden 验收完成前，UI V3 仍是 Target，不能描述为已上线。
- 生成图片保留在仓库外作为评审证据；仓库只提交设计合同和由真实组件生成的 Golden Screenshots。

## 7. 用户场景

### 尚未建立旅行

- 第一主操作是导入已有订单或行程材料，AI 创建旅行为第二入口，手动创建为次要入口。
- 空状态说明导入后得到的结果，不展示功能目录、示例功能卡或技术能力。

### 出发前

- 首页突出准备完成度、最近出发日期和真正阻塞出行的一项问题。
- 一键智能修复处理可自动修复的问题，其余进入一个合并确认。
- 票据和资料从真实缩略图编辑式列表进入，不先展示设置和统计。

### 旅行中

- 首页默认进入“今日”，优先显示下一站、时间、导航和票据。
- 只有正在移动或需要空间判断时地图占据首屏主要面积；等待、停留和到达状态优先显示动作对象。
- 延误、闭馆和天气变化只在有来源且影响当前行程时显示。
- 用户单手即可完成查看下一站、打开导航和出示票据。

### 旅行后

- 首页把已结束旅行降级为历史列表。
- 费用汇总、资料归档和旅行总结成为主要后续动作。
- 不继续显示出发前建议或过期实时提醒。

旅行阶段可以改变页面内容优先级，但不能改变全局导航位置和名称。

## 8. 信息架构

### 移动端主导航

底部导航固定为四项：

```text
今日 | 行程 | 资料 | 我的
```

- `今日`：按未建旅行、出发前、旅行中和旅行后切换的行动首页。
- `行程`：日期、时间线、地图视图和地点详情。
- `资料`：票据、订单、证件和待整理材料；默认作用于当前旅行，也可切换全部旅行。
- `我的`：账户、旅行偏好、通知、数据和高级设置。

底部导航只用于顶层页面，不放置 AI、添加、搜索等命令。Tab 名称必须是单个短词，不动态隐藏，不因页面状态禁用。

### AI 与搜索

- AI 是标题栏右侧的 `Sparkles` 图标命令，不是底部 Tab。
- 点击 AI 打开上下文 Action Sheet；用户跳转到结果页面后自动关闭。
- 搜索是标题栏或内容内的上下文命令，不占用独立底部 Tab。
- 全局搜索和 AI 可以共享目标解析，但视觉上仍明确区分“搜索已有内容”和“执行 AI 动作”。

### 行程内部结构

- 日程是默认内容，地图是同一日程的视图切换，不再与资料和费用组成四项标签栏。
- 删除独立“总览”层，其内容分配到“今日”和“日程”。
- 页面标题、旅行名称和日期在一个视口中只能出现一次。
- 地点详情使用 Push 导航；费用、同行、旅行设置和导出进入旅行 More 或对应对象入口。
- 从行程打开票据时进入一级“资料”的对应对象，并保留返回行程的上下文。

### 平板与桌面

- `600–1023px`：底部导航转换为 Navigation Rail 或顶部稳定导航；日程与详情可使用双栏。
- `>=1024px`：使用侧边导航和列表/详情主从布局。
- 桌面不得继续显示为居中的窄手机长条，也不得把移动卡片简单拉宽。

## 9. App Shell

- 顶栏包含返回、唯一页面标题、最多两个页面级命令。
- 次要命令进入 More 菜单；删除等破坏性操作不得占据主工具栏。
- 移动底部导航高度为 `56px + env(safe-area-inset-bottom)`。
- AI 关闭时不保留输入框、上下文标签或空面板。
- 页面底部 padding 由 App Shell 统一计算，不允许各页面使用超大固定 padding 猜测遮挡高度。
- 全高壳层必须先声明 `100vh` 回退，再声明 `100dvh/100svh`；支持动态视口的浏览器使用新单位，旧 Android WebView 仍必须铺满可见高度。
- 同一时刻最多存在一个固定底部交互面：主导航、Modal Sheet 或地图详情 Sheet。
- Modal 打开时可以覆盖底部导航，关闭后恢复原页面和触发按钮焦点。

## 10. AI Action Sheet

### 入口

- 所有主要业务页面使用同一个图标、位置和可访问名称“AI 助手”。
- 上下文自动取自当前 Trip / Day / Item / Ticket，不要求用户手动选择“当前页面/全部旅行”。
- 需要更换范围时，在 Sheet 标题栏提供紧凑菜单。

### 结构

1. 当前上下文标题。
2. 一个多行输入框。
3. 必要时显示一句计划摘要、步骤数和影响对象。
4. 一个主操作：执行、确认执行、打开结果或重试失败项。
5. 步骤详情默认折叠。

### 行为

- 只读导航和本地查找可自动完成，并立即关闭 Sheet。
- 旅行写入必须显示真实预览，并只出现一次最终确认。
- 部分失败只显示短结果和“重试失败项”，不重复成功步骤。
- 计划过期、目标歧义和 Provider 不可用显示一句可恢复错误，不展示堆栈或原始响应。
- 长任务收起为紧凑状态，不长期覆盖当前行程。
- Sheet 在移动端最高 `72dvh`；键盘打开时保证输入框、关闭按钮和主操作可见。
- 平板和桌面可以使用最大宽度 `420px` 的右侧 Dialog，但必须复用同一状态和无障碍合同。

### 无障碍

- 使用 `role="dialog"`、`aria-modal="true"` 和可见标题。
- 打开时焦点进入 Sheet，Tab 焦点不能逃出，Escape 关闭。
- 关闭后焦点返回触发 AI 的按钮。
- 执行状态使用 `aria-live="polite"`，错误信息与对应输入或主操作建立关联。

## 11. 页面规范

### 今日

- 删除宣传式“管家”Hero、重复统计和大块建议。
- 无当前旅行时以“导入已有材料”为主操作，AI 创建和手动创建降为次级入口。
- 出发前首屏采用 Selected Target 的高效信息结构：出发时间和倒计时、唯一阻塞项、机票/住宿/保险等已就绪真实对象，以及至多一条影响准备的事实；不默认展示地图。
- 旅行中首屏显示下一步、出发时间、导航和票据；正在移动时地图可以成为主要视觉。
- 旅行后首屏显示费用确认、资料归档和旅行回顾，不继续显示导航或出发前提醒。
- 有来源且影响当前决定的变化只显示最高优先级一项和对应操作。
- 多趟旅行使用普通列表；已结束旅行默认折叠或放在历史区。

### 日程

- 日期条保持紧凑并可横向滚动，选中日期不改变组件高度。
- 日程使用一条稳定时间轴和轻量分隔，不把每个行程点包成厚重卡片。
- 行程点默认显示时间、名称、地点和必要状态。
- 编辑、删除、移动进入滑动操作或 More 菜单；必须保留非拖拽替代操作。
- “添加行程点”使用标题栏加号或时间线末尾明确命令，不同时出现多个添加入口。

### 地图

- 地图是全屏内容，不放入装饰卡片。
- 顶部只保留返回、日期、列表/地图切换和最多一个 More 菜单。
- 选中地点后出现一个可拖动底部 Sheet；未选中时不默认占据大面积。
- 地点 Sheet 与 AI Sheet 不能同时展开。
- 地图控件、Marker、Sheet、导航和安全区不能互相遮挡。
- 动态地图不使用像素截图作为唯一验收，必须验证 canvas 非空、Marker 可见和控制区域无重叠。

### 地点详情

- 无真实地点照片时不显示渐变或占位 Hero。
- 有可检查的真实照片时才使用内容图，并保持地点主体可见。
- 首屏显示名称、时间、地址、导航和关联票据。
- 地址、坐标和外部地图入口不得在多个区块重复。
- 内容顺序为：现场操作、地点信息、票据、备注、更多。
- 重排偏好、坐标校正和 Provider 诊断进入二级“更多”页面。

### 资料

- 页面默认显示当前旅行的真实票据、订单和证件；待整理数量只作为状态或 Badge，不建立独立顶层页面。
- 有可预览资料时首先看到 Selected Target 的编辑式列表：左侧真实缩略图，右侧名称、类型、日期和一项关键元数据；默认不使用双列卡片画廊。
- 图片、二维码和证件使用真实缩略图；PDF 使用第一页预览；其他文件使用可识别但克制的文件行。
- 列表缩略图使用稳定横向预览槽；包含二维码和完整票面的资料优先 `object-fit: contain`，地点或酒店照片可以 `cover`，不得裁掉关键票务内容。
- 添加/导入使用标题栏命令；筛选、排序、旅行范围和批量选择进入 Sheet。
- 分类最多保留一行，零数量分类默认隐藏。
- 列表中长名称最多两行，详情中完整展示。
- 空状态只有一句原因和一个上传/导入主操作。

### 待整理材料

- 待整理是“资料”内的工作队列，可由 Badge、分区或筛选进入，不占底部导航。
- 有待处理资料时直接显示紧凑列表，无资料时不渲染空的待整理区。
- 不在首屏展示四个零统计、Provider 可用性或连接器技术说明。
- 来源设置进入二级“来源与导入”。
- AI 自动分类只显示短状态：处理中、待确认、已归档、失败。
- 批量确认使用一个合并预览，不要求逐条打开长表单。

### 设置

一级固定为四组：

```text
账户与同步
旅行偏好
应用与通知
数据与高级
```

- 一级只显示标题、必要状态和 Chevron，内容默认收起。
- Provider、配额、缓存、路线服务、设备存储和技术性隐私说明进入“数据与高级”。
- 普通用户只看到“已同步、等待网络、需要登录”等任务语言。
- 诊断信息必须与普通设置分离，不能用大块说明占据主页面。

### 编辑表单

表单分为：

1. 基本信息：标题、开始时间和必要结束时间。
2. 地点：地点搜索、候选、地址。
3. 更多设置：交通、跨时区、坐标、备注和高级规则。

- 第一屏只展开基本信息和地点。
- 国家/地区默认从旅行和地点候选推断，必要时才手动选择。
- 保存按钮在软键盘和安全区下仍可见，但不能再叠加第二个固定操作栏。
- 验证错误贴近字段，保存失败保留用户输入。

## 12. 视觉 Tokens

### 字体

```css
font-family:
  -apple-system,
  BlinkMacSystemFont,
  "SF Pro Text",
  "PingFang SC",
  "Microsoft YaHei",
  "Segoe UI",
  sans-serif;
```

- 中文界面优先使用系统字体，不再依赖 Plus Jakarta Sans 作为主要标题字体。
- 全产品最多两套字体；数字可以使用同一系统字体的 tabular numbers。
- 字号不随 viewport 连续缩放，letter-spacing 固定为 `0`。

### 字号

| Token | 字号 / 行高 | 用途 |
| --- | --- | --- |
| `display` | `28 / 34` | 顶层页面标题 |
| `title` | `20 / 28` | 主要对象标题 |
| `section` | `17 / 24` | 区块标题 |
| `body` | `15 / 22` | 正文和表单 |
| `meta` | `13 / 18` | 日期、来源和次要状态 |
| `label` | `11 / 16` | 底部导航和紧凑标签 |

### 间距

基础序列：

```text
4 | 8 | 12 | 16 | 24 | 32
```

- 手机水平页面边距 `16px`。
- 平板边距 `24px`。
- 桌面主内容边距 `32px`，并由主从布局控制阅读宽度。
- 同类行间距 `8–12px`，区块间距 `24px`。

### 颜色

所有组件必须使用语义 Token，不直接使用页面私有颜色。

| Token | Light 基准 | 用途 |
| --- | --- | --- |
| `background` | `#F7F9F8` | App 背景 |
| `surface` | `#FFFFFF` | Sheet、Dialog、独立对象 |
| `surface-subtle` | `#EFF4F2` | 轻量分组 |
| `text` | `#15201E` | 主文字 |
| `text-muted` | `#5E6B68` | 次要文字 |
| `border` | `#DDE5E2` | 分隔线 |
| `primary` | `#0E7C73` | 主操作、选中状态 |
| `secondary` | `#D05A47` | 少量品牌强调 |
| `success` | `#18794E` | 成功 |
| `warning` | `#9A5B00` | 警告 |
| `danger` | `#B42318` | 删除、阻塞错误 |

深色模式使用独立语义值，不能简单反转或用一组深蓝/墨绿统治整个界面。主色、警告、成功和错误在深色背景上必须重新验证对比度。

### 圆角与层级

- 卡片、按钮、输入框和行组件最大圆角 `8px`。
- Bottom Sheet 顶部圆角可以为 `12px`。
- 普通页面不使用阴影。
- 浮层只使用一个统一 elevation，不创建多级装饰阴影。
- 禁止卡片嵌套卡片。

### 动效

- 标准过渡 `160–220ms`。
- 页面 Push、Sheet 和状态变化使用一致 easing。
- 动效不能导致控件位置跳动或改变固定组件尺寸。
- 支持 `prefers-reduced-motion`，关闭非必要移动和缩放。

## 13. 组件合同

V3 优先建立以下共享组件：

- `AppScaffold`：唯一的安全区、顶栏、导航和内容布局所有者。
- `ContextHeader`：返回、唯一标题、AI、Search 和 More。
- `PrimaryNavigation`：移动 Tab、平板 Rail、桌面 Sidebar 的自适应实现。
- `Section`：无卡片的语义区块。
- `StatusStrip`：一行可操作状态，不扩展为诊断卡。
- `RecordRow`：设置、资料和元数据行。
- `TimelineRow`：稳定时间轴行和上下文操作。
- `DocumentThumbnail`：图片、PDF、二维码和文件状态。
- `AiActionSheet`：AI 输入、计划、确认、结果和重试。
- `FilterSheet`：筛选、排序和批量选择。
- `DisclosureRow`：默认收起的二级设置。
- `FormSection`：基本、地点和高级字段的渐进披露。

共享组件必须定义默认、hover、pressed、focus、disabled、loading、error、empty、selected、long-content 和 dark-mode 状态。页面不得复制一套私有按钮、状态条或 Sheet。

## 14. 内容与文案

- 产品文案默认使用中文。
- 标题应说明对象，不解释页面功能。
- 主按钮使用明确动词，例如“打开票据”“开始导航”“确认执行”。
- 禁止在普通页面显示 schema、Provider、quota、cache、snapshot、revision 等技术词。
- AI 结果默认为一句摘要、影响对象和一个主操作。
- 不使用“现在建议做什么”之类占据首屏的大标题。
- 不把隐私、安全或离线能力包装成营销文案；只在用户需要作出选择时简短说明。
- 时间、价格、营业和交通等实时事实必须带来源与新鲜度；来源信息放在详情或紧凑元数据中。
- 不显示无法证实的实时状态，不用模型推测填补 Provider 失败。

## 15. 状态规范

| 状态 | 展示规则 |
| --- | --- |
| Loading | 使用与真实内容结构一致的 Skeleton，不显示整页 Spinner |
| Empty | 一句原因、一个主操作，不展示零统计 |
| Offline | 仅在影响当前操作时显示一行状态，并说明可继续做什么 |
| Stale | 显示最后更新时间；不得继续标为当前实时事实 |
| Provider failure | 使用用户任务语言和重试，不展示 Provider 名或原始错误 |
| Partial success | 显示完成数量、失败数量和“重试失败项” |
| Long content | 列表最多两行，详情完整展示；容器不得横向溢出 |
| Destructive | 说明影响对象，默认焦点放在非破坏性操作 |
| Background job | 使用紧凑状态，可离开当前页面继续执行 |

所有 Flex/Grid 用户内容项必须允许收缩，并测试中文、英文、无空格文件名和超长地址。

## 16. 无障碍

目标为 WCAG 2.2 AA，同时采用更适合触屏旅行场景的产品标准：

- 所有触控目标至少 `44 x 44px`；主要按钮高度 `48px`。
- 普通正文对比度至少 `4.5:1`；大型文字、图标和控件边界至少 `3:1`。
- 支持浏览器文字放大到 `200%`，不丢内容、功能或阅读顺序。
- 所有操作可通过键盘完成，焦点顺序与视觉顺序一致。
- 焦点指示必须清晰，并且不被顶栏、Sheet、软键盘或底栏遮挡。
- 图标按钮必须有可访问名称；Tooltip 不能是唯一说明。
- 状态不能只依赖颜色，必须同时使用文字或图标语义。
- Tabs 使用 `tablist/tab/tabpanel` 合同；Modal 使用 APG Dialog 合同。
- 拖动、滑动和地图手势必须有按钮或菜单替代方案。
- 实时和 AI 状态使用克制的 live region，避免重复朗读。

## 17. 性能与稳定性

- 保持现有 bundle budget；AI、MapLibre、PDF、OCR 和 JSZip 不得重新进入静态启动图。
- 首屏只加载当前页面必需组件和真实缩略图。
- 图片和 PDF 缩略图延迟加载，列表滚动不因异步内容发生明显跳动。
- 生产目标：LCP `<=2.5s`、INP `<=200ms`、CLS `<=0.1`。
- Sheet、时间线和地图交互目标为稳定 60fps；低端设备不得因阴影、模糊和大面积滤镜持续重绘。
- 页面切换必须保持导航尺寸稳定，加载标签和长文字不能推挤布局。

## 22. 已锁定决策

- V3 是信息架构和 App Shell 重构，不是局部换肤。
- 产品定位和用户任务先于视觉方向；已否决的地图主导效果图属于 Historical。
- Selected Target 为“第一套左上角出发前首页 + 第二套整体视觉 + 第三套资料列表”；实现不得逐页重新发明视觉语言。
- UI 设计使用 MCP 和生成工具，但真实代码与 Golden Screenshots 才是最终视觉依据。
- Figma 是可选协作镜像，不是实现前置条件。
- 底部导航固定为 `今日 | 行程 | 资料 | 我的`；AI 和搜索是 Toolbar 命令。
- 全局 AI 改为按需 Action Sheet，写入继续预览加一次最终确认。
- “今日”以旅行阶段和下一步为中心；地图不是所有阶段的默认首页。
- 卡片只表达独立对象，页面区块不再普遍卡片化。
- 真实票据缩略图优先，禁止文件类型头图替代可预览内容。
- 高信息量通过真实对象、稳定分组和清晰层级实现，不通过缩小字号、大段说明、重复摘要或卡片堆叠实现。
- 移动、平板和桌面采用不同导航布局，但共享同一组件和语义。
- 技术诊断、安全机制和 Provider 状态不占普通用户主路径。
